# 如果它是一个产品

**这是设计预案，不是现状。** 现状在[这个项目是哪一类](./positioning.md)那张表里，九格都是判断，不是待办。

## 一句话结论

把九个维度从「现在是什么」改成「换成什么形态该补什么」，答案几乎都不在流程上，而在**一个身份**：谁在装、装到哪、装的是哪一版。三种形态在每一格里可能同时出现，所以每格都点名：**多人协作**（会克隆、会改、会报问题的第二个人）、**团队内部服务**（10 到几十人共用一条流水线）、**有外部用户的工具**（拿不到源码 diff 的使用者）。

| # | 维度 | 现在的答案 | 换成那个形态时补什么 · 触发条件 · 代价 |
| --- | --- | --- | --- |
| 1 | 构建与打包 | [存在](./delivery.md)：整树拷贝 + 可复现 zip | 多人协作：版本化载荷 + 依赖清单。触发是出现第一处「我改了载荷」；代价是清单会漂 |
| 2 | 发布 | [存在，规模极小](./delivery.md)：仓库 + `INSTALL.md` | 有外部用户：安装器 + 校验和 + 「装了什么」清单。触发是要在别人机器上复现一个装坏的环境；代价是多一个会过期的程序 |
| 3 | 更新方式 | [不存在](./delivery.md)：整包覆盖，不记录版本 | 多人协作：自检 + 提示 + 可选自动更新。触发是第二个人要知道该不该升；代价是载荷里出现第一个主动联网的组件 |
| 4 | 版本管理 | 存在：`package.json` 单一来源、三个 annotated tag | 团队内部服务：tag 触发构建、产物留档。触发是有人问「线上是哪个 commit」；代价是交出 `git tag -f` 的自由 |
| 5 | 灰度 | [不存在](./rollback.md)：唯一用户是作者 | 有外部用户：内部 dogfood 通道 + 显式版本切换。触发是第一次「新版可能更差」；代价是两版要并存 |
| 6 | 回滚 | [部分存在](./rollback.md)：可重建，不可回滚 | 有外部用户：保留 N 个产物 + 安装处版本标记。触发是第一次真想退回上一版；代价是存储与清理策略 |
| 7 | 日志与指标 | [部分存在](./observability.md)：留痕齐全，成本与质量拦截没落盘 | 团队内部服务：远端埋点。触发是第二个人开始看指标；代价是先定下哪些数据可以离开本机 |
| 8 | 鉴权 | [不存在](./positioning.md)：没有用户体系 | 团队内部服务：技能包的信任模型，不是账号系统。触发是把第三方 skill 当依赖；代价是多一个能被绕过的门 |
| 9 | 可观测性 | [部分存在](./observability.md)：5 类 id，无 exception id | 任何形态：异常 id + 跨进程 trace。触发是第一次要把失败从子进程串回父会话；代价是每一层都要认那个 id |

## 九条各自展开

**1 · 构建：清单越细越好用，也越容易忘。** 多人协作要的是「按账本核对」，而不是按目录树复制。代价不是假想的：[拒绝优于降级](../design/refuse-not-degrade.md)记着一次，新增的顶层目录既不进载荷、也不在 `FORBIDDEN` 里，**不发声地没有被拷贝**。

**2 · 发布：安装器是唯一一处「它的 bug 挡住所有人」的代码。** 有外部用户要补的，是把那几步 `cp -r`、改 `verify:`、钉 `shellPath`、接受项目信任做成一个能重跑的程序。今天这个风险不存在，因为装坏了直接重装。

**3 · 更新：自检是唯一会主动对外说话的东西。** 现在没有代码读自己的版本。补上之后，「这个项目不联网」这句话就得重写——而它现在正是[埋点](./observability.md)整页的前提。

**4 · 版本：tag 从标签变成合同。** 团队内部服务要求 tag 一旦推出就必须能重建出同样的东西。现在「不可变是约定不是机制」：没有东西阻止 `git tag -f`，CI 也不校验 tag 与内容一致。变成合同，这份自由就得交出。

**5 · 灰度：两个前提都不成立。** 它要「有少数人可选」和「能观察他们」。最小形态不是百分比，而是两版并存加一份能判断要不要升的 CHANGELOG 分级。并存要求安装处记版本——灰度拖着一格一起下水。

**6 · 回滚：最便宜的一格。** 有外部用户时，补的不是流程，是一个能被读到的字段（版本标记）加一份产物留存。`dist/` 被 gitignore、`build()` 会 rmtree、epoch 只写在产物内部，所以今天能做的只有重建后重新部署。

**7 · 指标：先决定哪些数据可以离开本机。** `usage` 死在 tool call 里，verify 门拦过几次只在会话内存里。远端埋点要把它们变成事件发出去，而这个决定一旦做出就再也不能假装没做——`RunEntry` 里本来就存着会话语义。

**8 · 鉴权：这一格我建议换成别的问题。** 真正的缺口不在账号，在第三方 skill 的来源：`.pi/settings.json` 把它们写成 `git:github.com/...`，不带 commit 也不带 tag，`.pi/git/` 整个被忽略。而且最锋利的那条洞就在这类守卫上：`channel.py` 起 worker 时不设 `MYFLOW_AGENT_TYPE`，那个 worker 在扩展眼里是一个主会话。

**9 · 可观测性：id 要每一层都认。** 五个 id 都在，缺的是 exception id 与跨进程 trace；子代理是 `--no-session`，一次子运行的唯一身份是 `runId` 加一个**文件名里没有 `runId`** 的日志。代价不是加一个字段，是每一层都愿意传它。

## 哪一条我永远不会做

**灰度，以及它背后那句期待：让别人的机器先替我踩。**

它要求一件我不打算提供的东西：一个我不知道内容的运行环境，作为我的默认值。灰度只在「用户之间的差异不是我能想象完的」时才有价值；一旦有第二个人，我该做的是维度 2 的安装器和维度 6 的版本标记——让**他**能干净地退回上一版，而不是让**我**用他的机器测一版。

其余八条我都可能补。唯独这一条，补上的那天说明我已经在做另一个产品了。
